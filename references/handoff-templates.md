# 交接包模板

交接模式生成或刷新 `.handoff/` 下 5 个文件和入口跳板时，按本模板填写。模板里 `<尖括号>` 是要填的内容，注释是填写指引，不要照抄指引文字本身。

## 通用规则

1. 每个文件第一行写一句"何时读我"，让新 agent 能判断要不要读这个文件。
2. 每个文件顶部写最后更新时间。
3. 大文件、代码、长日志不复制原文，只在 index.md 记路径和关键行。
4. 敏感信息只记"存在该文件"，不记值。

## 1. 入口卡 .handoff/HANDOFF.md（唯一必读，目标不超过 400 字）

````markdown
# 项目交接入口卡

> 交接时间：<YYYY-MM-DD HH:mm> ｜ 来源 agent：<工具名> ｜ 项目根：<项目目录名> ｜ <如是降级交接（无原会话上下文）在此标注"降级交接"，否则省略>

## 这个项目是什么
<一句话：项目名称 + 在做什么 + 给谁用>

## 项目目标
- 最终目标：<这个项目最终要达成什么>
- 当前阶段目标：<当前阶段要做到什么>

## 现在的状态（一句话）
<例如：核心功能已完成约七成，正在做用户登录，下一步补前端表单>

## 给新 agent 的接手指令
1. 你已经读完本入口卡，这是唯一必读文件。
2. 对齐上面的"项目目标"，再按当前要做什么，去读下面这些文件（每个文件第一行写着"何时读我"，不需要的可跳过）：
   - status.md：了解进度、未完成任务、下一步
   - decisions.md：了解关键决策、约定与禁忌
   - capabilities.md：了解项目命令和工作流
   - index.md：查关键文件位置
3. 读完后用几句话向用户复述"你理解的现状 + 你建议先做的下一步"，等用户确认后再动手。
4. 开始干活后，把 status.md 当作活档案持续更新。

## 紧急 / 高危提醒（没有就删这一节）
<例如：连着生产数据，禁止直接改生产库>
````

## 3. 决策与禁忌 .handoff/decisions.md

````markdown
> 何时读我：当你需要了解为什么这么设计、有什么约定和禁忌、之前踩过什么坑时读本文件。
> 最后更新：<YYYY-MM-DD HH:mm>

## 约定与禁忌（最重要，先读这块）

### 要遵守的约定
- <例如：改完代码必须跑 <某测试>；代码风格遵循 <某规范>；提交信息格式 <某格式>>

### 禁忌 / 不要做的事
- <例如：不要动 <某文件>；不要直接改生产配置；不要引入新的重型依赖>

## 关键决策（为什么这么做）

### D1 <决策标题>
- 决策：<定了什么>
- 原因：<为什么这么定，而不是别的方案>
- 用户原话（如有）：<与该决策相关的用户原话，保留原表达，没有可省略此行>

### D2 <决策标题>
- 决策：<定了什么>
- 原因：<为什么这么定>

## 踩过的坑
- <坑 + 当时怎么解决或怎么绕开的>
````

## 4. 能力与工具 .handoff/capabilities.md

````markdown
> 何时读我：当你需要知道这个项目怎么构建、运行、测试，或上一个 agent 用了哪些工具时读本文件。
> 最后更新：<YYYY-MM-DD HH:mm>

## 项目命令与工作流（工具无关，最值钱）
- 安装依赖：<命令>
- 本地运行：<命令>
- 构建：<命令>
- 测试：<命令>
- 部署：<命令或说明>
- 常用工作流：<例如：改代码 → 跑测试 → 提交>

## 上一个 agent 用过的工具 / skill（供参考）
- <工具或 skill 名 + 用它做了什么>
- 说明：换到不同工具时这些名字可能不适用，请在新工具里找等价能力。
````

## 6. 入口跳板（项目根目录，按目标工具选一个）

内容统一只有一句话，指向交接包。

- Claude Code 用 `<项目根>/CLAUDE.md`
- Cursor 用 `<项目根>/.cursorrules`（或 `.cursor/rules/`）
- 其他或不确定用 `<项目根>/AGENTS.md`

````markdown
本项目有交接包。开始任何工作前，请先读 `.handoff/HANDOFF.md` 并按里面的接手指令操作。
````
